# Discord 401 Investigation — 2026-08-24 ~23:15

## Root Cause
The Discord bot token was fine. The 401 came from the **model provider** (Parasail / Kimi K3), not Discord itself.

The running gateway process was holding **stale in-memory config** from before the Parasail credential migration. The on-disk `openclaw.json` already had the new `parasail/` provider ID, but the live gateway never reloaded and was still using the old `custom-api-parasail-io/` ID with the old API key.

Evidence: Discord trajectory log at 23:09:47 showed:
```json
"model":{"provider":"custom-api-parasail-io",...}
"agents":{"defaults":{"model":{"primary":"custom-api-parasail-io/moonshotai/Kimi-K3"}}}
```

## Fix
Restarted the OpenClaw gateway process (`openclaw gateway restart`). This forces it to re-read openclaw.json and pick up the new `parasail/` provider ID with the current API key.

## Update (2026-08-25 19:30)
Root cause was deeper than stale config: Brad migrated from Parasail to **Baseten** entirely. The old Parasail API key was deactivated, causing the 401s. Config was already updated to `baseten/moonshotai/Kimi-K3` as default — gateway just needed a restart to pick it up.

## Status
Gateway restarted at 19:30 EDT on Baseten config. Health check OK, Discord plugin loaded. Waiting for Brad to test a Discord message.
